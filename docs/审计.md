## 一、关键问题（必须修复）

### 1.1 Gateway 来源的生成记录重试必定 422 失败

- **文件**：`apps/server/src/routes/generate.ts`（重试 handler）
- **问题**：重试时从 `inputParams` 信封中剥离了 `source`、`projectId`、`shotId`、`referenceFileIds`，但**遗漏了 `requestedModel`**。`validateModelParameters`（`packages/provider/src/model-validator.ts`）会拒绝所有不在模型参数声明中的字段。`requestedModel` 是 OpenAI Gateway（`openai-gateway.ts`）写入的信封字段。
- **影响**：所有通过 OpenAI Gateway（`/v1/chat/completions`）发起的生成记录，失败后通过 `POST /api/records/:id/retry` 重试时**必定返回 422**：`未知参数 "requestedModel"`。
- **修复**：在重试 handler 的剥离逻辑中增加 `delete rawParameters.requestedModel`。

### 1.2 drizzle-orm 版本冲突 — 安装了两个不兼容版本

- **文件**：
  - `package.json`（根）：`"drizzle-orm": "^0.45.2"`
  - `apps/server/package.json`：`"drizzle-orm": "^0.44.2"`
  - `apps/worker/package.json`：`"drizzle-orm": "^0.44.2"`
  - `packages/db/package.json`：`"drizzle-orm": "^0.44.2"`
- **问题**：`^0.44.2`（范围 `>=0.44.2 <0.45.0`）和 `^0.45.2`（范围 `>=0.45.2 <0.46.0`）**完全不重叠**。`bun.lock` 确认安装了两份独立副本：`0.45.2` 和 `0.44.7`。磁盘膨胀 + 类型不兼容风险。
- **修复**：
  - `packages/db/package.json` 升级为 `"drizzle-orm": "^0.45.2"`
  - `apps/server` 和 `apps/worker` 移除 drizzle-orm 直接依赖（两者 src/ 中 0 处直接 import drizzle-orm，均通过 `@excuse/db` 间接使用）
  - 重新 `bun install` 收敛到单一版本

### 1.3 Dockerfile CMD 引用不存在的 .env 文件

- **文件**：`Dockerfile`
- **问题**：`CMD ["bun", "--env-file", ".env", "apps/server/src/index.ts"]` 但 Dockerfile 三个阶段（build、runtime-deps、server/worker）**均未 `COPY .env .env`**。`docker-compose` 部署时 `env_file: .env` 注入环境变量所以无害，但 `docker run` 直接运行镜像时环境变量不会被加载。
- **修复**：移除 `--env-file .env`，依赖容器环境变量：
  ```diff
  - CMD ["bun", "--env-file", ".env", "apps/server/src/index.ts"]
  + CMD ["bun", "apps/server/src/index.ts"]
  ```

## 二、警告级问题（应该修复）

### 2.1 OpenAI Gateway 流式/非流式计费编排逻辑重复（~200 行）

- **文件**：`apps/server/src/routes/openai-gateway.ts`（流式 handler）vs `apps/server/src/services/gateway-service.ts`（非流式 handler）
- **问题**：两条路径各自完整实现了相同的编排流程：创建生成记录 → 预留额度 → 调用 provider → 成功扣款/失败退款 → 审计日志。且存在行为差异：非流式路径（`gateway-service.ts`）**缺少 `incrementApiKeySpend` 和 `notifyApiKeyQuota`**，而流式路径（`openai-gateway.ts`）有这些调用。即通过非流式 Gateway 调用不会触发 API Key 额度追踪和通知。
- **修复方向**：将共用步骤抽为 `beginGatewayRecord` / `finalizeGatewayRecord` / `failGatewayRecord` 三阶段函数，流式和非流式共用，仅 provider 调用部分各自实现。确保 `incrementApiKeySpend` 和 `notifyApiKeyQuota` 在两条路径中均执行。

### 2.2 `centsToYuan` 函数在 billing 包内两处重复定义

- **文件**：`packages/billing/src/calculate.ts` 和 `packages/billing/src/statistics.ts`
- **问题**：完全相同的 `function centsToYuan(cents: number): number { return Math.round(cents * 100) / 10000 }` 各自定义。金额计算精度逻辑若修改需两处同步。
- **修复**：提取到 billing 包内共享工具文件，两处 import 使用。

### 2.3 admin 路由 API Key 序列化逻辑重复

- **文件**：`apps/server/src/routes/admin.ts`（`GET /users/:id/api-keys` 和 `GET /gateway-clients/:accountId`）
- **问题**：完全相同的 API Key 字段映射在两处各写一遍。与 `api-keys.ts` 已有的 `serializeApiKey` 形成三处维护。
- **修复**：提取 `serializeAdminApiKey(key)` 函数，两处复用，并与 `api-keys.ts` 的序列化对齐。

### 2.4 Server 与 Worker 之间 `loadOSSConfig()` 和 `isPublicMetricsCidrs()` 逐行相同

- **文件**：
  - `apps/server/src/config.ts` 的 `loadOSSConfig()` / `isPublicMetricsCidrs()`
  - `apps/worker/src/config.ts` 的 `loadOSSConfig()` / `isPublicMetricsCidrs()`
- **问题**：逐行相同的函数在两端各自维护。
- **修复**：迁移到 `@excuse/shared` 包导出。

### 2.5 `formatMs()` 在 SubtitleEditor 中与 generation-utils 逐字节重复

- **文件**：`apps/client/src/pages/SubtitleEditor.tsx`（第 37-42 行本地定义）vs `apps/client/src/lib/generation-utils.ts`（已导出的 `formatMs`）
- **问题**：`SubtitleOutputPreview.tsx` 已正确从 `generation-utils.ts` 导入，但 `SubtitleEditor.tsx` 本地重新定义了一份。时间格式若修改需两处同步。
- **修复**：删除本地定义，改为 `import { formatMs } from '@/lib/generation-utils'`。

### 2.6 字幕状态常量 `STATUS_LABELS` / `STATUS_COLORS` 跨文件重复

- **文件**：`apps/client/src/pages/Subtitle.tsx` 和 `apps/client/src/pages/SubtitleEditor.tsx`
- **问题**：7 个字幕状态的标签和颜色映射完全相同，定义在两个文件中各写一遍。新增或修改状态需同时更新两处。
- **修复**：提取到 `lib/subtitle-constants.ts` 或 `stores/subtitle.ts`，两处 import 使用。

### 2.7 剪贴板复制函数在 4 个页面重复定义

- **文件**：`apps/client/src/pages/ApiKeys.tsx`、`Assets.tsx`、`ModelLab.tsx`、`Developers.tsx`
- **问题**：四个页面各自定义了功能完全相同的剪贴板复制函数（仅函数名不同：`copyToClipboard` / `copyLink` / `copyText` / `copyCode`），实现都是 `navigator.clipboard.writeText()` + toast 提示。
- **修复**：提取到 `lib/utils.ts`：
  ```typescript
  export async function copyToClipboard(text: string, successMsg = '已复制') {
    try {
      await navigator.clipboard.writeText(text)
      toast.success(successMsg)
    } catch {
      toast.error('复制失败')
    }
  }
  ```

### 2.8 `CATEGORY_LABELS` 在 Admin 与 Billing 定义不一致

- **文件**：`apps/client/src/pages/Admin.tsx` 和 `apps/client/src/pages/Billing.tsx`
- **问题**：两个文件都叫 `CATEGORY_LABELS`，但值不同：
  - Admin.tsx：`text: '文本'`, `image: '图片'`, `video: '视频'`
  - Billing.tsx：`text: '文本生成'`, `image: '图像生成'`, `video: '视频生成'`
  
  新增 category（如 `audio`）需多处手动添加，且命名混淆。
- **修复**：使用更精确的常量名（`TASK_CATEGORY_LABELS` vs `BILLING_CATEGORY_LABELS`），或提取到共享模块。

### 2.9 tsconfig 不继承根配置，类型检查严格度不一致

- **文件**：`apps/server/tsconfig.json`、`packages/shared/tsconfig.json`、`packages/db/tsconfig.json`
- **问题**：三者不 extends 根 `tsconfig.json`，导致关键严格标志缺失：

  | 设置 | Root | Server | Worker (via root) | Shared/DB |
  |------|------|--------|-------------------|-----------|
  | `target` | `ESNext` | `ES2021` | `ESNext` | `ESNext` |
  | `noUncheckedIndexedAccess` | `true` | **false** | `true` | **false** |
  | `verbatimModuleSyntax` | `true` | **false** | `true` | **false** |
  | `noFallthroughCasesInSwitch` | `true` | **false** | `true` | **false** |

  Server 代码在更宽松的类型检查下编译，可能漏掉在 Worker/Packages 中会被捕获的问题。
- **修复**：让 server、shared、db 的 tsconfig 都 extends 根配置，仅保留各自必需的差异项（如 server 的 `bun-types`）。

### 2.10 Server 和 Worker 声明了未直接使用的 `drizzle-orm` 依赖

- **文件**：`apps/server/package.json`、`apps/worker/package.json`
- **问题**：grep 确认两者 src/ 中 0 处直接 import drizzle-orm，均通过 `@excuse/db` 间接使用。违反显式依赖原则。
- **修复**：移除两者的 `drizzle-orm` 直接依赖。

## 三、建议级问题（考虑优化）

### 3.1 Admin.tsx 过于庞大（2234 行），应拆分为独立组件文件

- **文件**：`apps/client/src/pages/Admin.tsx`
- **问题**：包含 6 个 tab 组件（Overview/Users/Providers/Projects/Gateway/Audit）、5 个手动 Dialog 弹窗、多个表格、表单，全部内联在单一文件中。严重影响可读性、可维护性和代码审查效率。
- **修复**：按 tab 拆分为 `pages/Admin/` 目录：`index.tsx`（Tab 框架）、`OverviewTab.tsx`、`UsersTab.tsx`、`ProvidersTab.tsx`、`ProjectsTab.tsx`、`GatewayTab.tsx`、`AuditTab.tsx`。

### 3.2 Admin.tsx 手动搭建 Dialog UI，绕过 Radix 无障碍特性

- **文件**：`apps/client/src/pages/Admin.tsx`（5 处 `<Dialog open={...}>`，分别位于行 693/934/1088/1404/1708）
- **问题**：内部用 `fixed inset-0 z-50` 手动搭建弹窗 UI，没有使用 `DialogContent`/`DialogHeader`。绕过了 Radix Dialog 的焦点陷阱（focus trap）、Escape 关闭、ARIA 属性和动画。其他页面已正确使用 `DialogContent`。
- **修复**：将手动弹窗替换为 `DialogContent` + `DialogHeader` + `DialogTitle`。

### 3.3 Developers.tsx 使用原始 fetch() 而非 Eden Treaty

- **文件**：`apps/client/src/pages/Developers.tsx`（`UsageSection` 的 `queryFn`）
- **问题**：使用 `fetch(\`${BASE_URL}/v1/usage\`, { credentials: 'include' })` 直接调用 Gateway API，绕过了 Eden Treaty 的类型安全。API 响应结构变更时不会在编译时捕获。
- **修复**：在 `api/` 目录通过 Eden Treaty 封装 `/v1/usage` 调用。

### 3.4 generation store 的 `fetchProjects` / `projectMap` 是死代码

- **文件**：`apps/client/src/stores/generation.ts`
- **问题**：定义了 `projectMap: Map<string, ProjectDTO>` 状态和 `fetchProjects()` 方法，但整个客户端应用中**没有任何组件**调用 `fetchProjects()` 或消费 `projectMap`。
- **修复**：删除 `projectMap` 状态、`fetchProjects` 接口声明和实现。

### 3.5 App.tsx 缺少 404 catch-all 路由

- **文件**：`apps/client/src/App.tsx`
- **问题**：`Routes` 中未定义通配路由（`<Route path="*" .../>`）。用户访问不存在路径时看到空白页面（Layout 内的空白 `<Outlet />`），没有任何提示。
- **修复**：在 Routes 末尾添加 catch-all 路由，显示"页面不存在"提示和返回首页链接。

### 3.6 SSE connect() 在三处调用，生命周期难追踪

- **文件**：`apps/client/src/api/client.ts`、`App.tsx`、`AuthProvider.tsx`
- **问题**：`sseClient.connect()` 在 `setAuthToken()`（登录/token 刷新）、`AuthProvider`（页面刷新）、`App.tsx`（检测 JWT）三处调用。虽然 `SSEClient.connect()` 内部有防重入保护，但三处调用使得连接生命周期难以追踪。
- **修复**：只保留一处权威调用点（推荐 `AuthProvider` 认证成功后），其他两处改为注释说明或直接移除。

### 3.7 `estimateCost` 导出但生产代码未使用

- **文件**：`packages/billing/src/calculate.ts`
- **问题**：被 `billing/index.ts` 导出，但仅在测试文件中使用。生产代码直接使用 `calculateCost()` 并手动标记 `estimated: true`。
- **修复**：要么在生产代码中使用 `estimateCost`（替换手动标记模式），要么从公开 API 中移除。

### 3.8 `health.ts` 和 `metrics.ts` 各自维护独立 `startTime`

- **文件**：`apps/server/src/routes/health.ts`、`apps/server/src/routes/metrics.ts`
- **问题**：两个路由文件各自有 `let startTime = Date.now()` 和对应的 `resetXxxStartTime()` 测试辅助函数。两个模块级可变状态增加认知负担。
- **修复**：将进程启动时间放入 server config 或 `@excuse/shared` 中作为不可变值。

### 3.9 Dockerfile 将全部源码 COPY 到生产镜像

- **文件**：`Dockerfile`（`runtime-deps` 阶段）
- **问题**：`COPY apps/ apps/` 和 `COPY packages/ packages/` 将所有 TypeScript 源码（含测试文件）复制到生产镜像。导致镜像体积增大和源码泄露。
- **修复方向**：`runtime-deps` 阶段只 COPY 各 workspace 的 `package.json`，不复制源码（仅用于 `bun install --production`）。

### 3.10 `currency.js` 版本声明不一致

- **文件**：
  - `package.json`（根）：`"currency.js": "^2.0.4"`
  - `packages/billing/package.json`：`"currency.js": "2"`
  - `apps/client/package.json`：`"currency.js": "2"`
- **问题**：`"2"` 是精确版本锁定，`"^2.0.4"` 允许 `2.x` 升级。版本声明策略不统一。
- **修复**：统一使用 `"^2.0.4"`。

### 3.11 Worker 声明了未直接使用的 `@excuse/canvas-engine` 和 `@excuse/prompt-engine`

- **文件**：`apps/worker/package.json`
- **问题**：grep 确认 worker src/ 中无直接 import，仅通过 `@excuse/canvas-runtime` 间接使用。
- **修复**：移除这两个直接依赖。
